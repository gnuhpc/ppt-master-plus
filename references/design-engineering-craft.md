# 设计工程与动画手艺标准 (Design Engineering Craft & Animation Standards)

本指南提炼自 Emil Kowalski 的设计工程哲学（[animations.dev](https://animations.dev)），旨在为 `ppt-master-plus` 演示文稿工具链提供高水准的“手艺（Craft）”指导，使生成的幻灯片不仅能正确呈现，而且在视觉与动态体验上极具品质。

---

## 一、核心设计哲学 (Core Philosophy)

### 1. 品味是训练出来的，而非天生 (Taste is trained, not innate)
好品味不是个人偏好，而是一种经过训练的直觉：超越显而易见的事物，识别出能升华体验的细节。在构建 UI 与 PPT 动态时，不要满足于“能跑就行”，要深入思考为什么优秀的界面会让人感觉舒适。

### 2. 未被察觉的细节会叠加复利 (Unseen details compound)
用户绝大多数时候不会有意识地注意到这些细节，但这正是目的所在。当一个功能完全按照人们假设的方式运作时，他们就会毫无阻碍地继续操作。
> "所有那些未被察觉的细节结合在一起，产生了一种令人惊叹的效果，就像一千个极其微弱的声音在完美合唱。" —— Paul Graham

### 3. 审美是杠杆 (Beauty is leverage)
人们选择工具和接受信息是基于整体体验，而不仅仅是功能。良好的默认值与得体的动画是真正的差异化因素。

## 二、动画决策框架 (Animation Decision Framework)

在为幻灯片添加任何进入动画或切换前，请按顺序回答以下问题：

### 1. 这是否需要动画？(Should this animate at all?)

| 频率 / 场景 | 决策 | 说明 |
| --- | --- | --- |
| 高频/快捷操作 (目录、导航、页码) | **不使用动画** | 每次都看到的导航元素加动画会显得拖沓 |
| 次高频 (卡片悬停、列表展开) | **极简或不使用动画** | 保持极简交互 |
| 阶段性元素 (卡片进入、图表渐现) | **标准进入动画** | 使用精致的缓动 |
| 稀有/首次 (封面、核心亮眼观点) | **精心设计的动画 (Delight)** | 增强视觉冲击力 |

**规则：高频导航与页面装饰元素绝不单独添加进入动画。**

### 2. 动画的目的是什么？(What is the purpose?)
每个动画都必须有明确的原因：
- **空间一致性 (Spatial consistency)**：如方向一致的进入/推入。
- **状态指示 (State indication)**：图表或步骤的逐步揭示。
- **解释说明 (Explanation)**：展示过程与因果关系。
- **防止画面突变 (Preventing jarring changes)**：避免无过渡的突兀硬切。

如果目的仅仅是“看起来酷”且频繁出现，请不要使用动画。

### 3. 缓动与时长要求 (Easing & Duration)
- **进入动画**：优先使用 `ease-out`（快速启动，给用户即时反馈）。**严禁对 UI 元素使用 slow `ease-in`**，因为它会在起始时刻产生推迟感，使用户觉得卡顿。
- **时长范围**：
  - 按钮/小标签：`100ms - 160ms`
  - 卡片/列表项：`200ms - 280ms`
  - 标准演示文稿默认元素进入：`400ms`（在自定义配置中，UI 细节元素推荐小于 300ms）
- **源头感知**：放缩动画应从 `scale(0.9)` 或 `scale(0.95)` 配合透明度渐变开始，**绝不要从 `scale(0)` 开始放大**（现实中没有物体从 0 点凭空变出）。

## 三、标准审查格式 (Required Review Format)

进行动画与视觉手艺审查时，**必须**使用包含 `Before | After | Why` 三列的 Markdown 表格格式：

| Before (修改前) | After (修改后) | Why (原因说明) |
| --- | --- | --- |
| `duration: 0.8s` (全页元素统一) | `duration: 0.25s` (卡片项) | 降低拖沓感，保持动态灵敏 |
| `scale(0)` 放大进入 | `scale(0.95)` + 透明度渐入 | 避免物体凭空突兀出现的假象 |
| 导航页码 `id="pagenumber"` 随内容淡入 | 导航页码 `effect: none` (保持静态) | 高频 chrome 元素不应参与卡片动画 |
| 统一使用 `random` 随机动画 | 依据组 ID (`chart` $\rightarrow$ `wipe`) | 保持语义与动画类型的一致性 |

## 四、自然语言动画词汇表映射 (Animation Vocabulary)

当用户使用自然语言描述动画效果时，映射到 `ppt-master-plus` 的原生 PPTX 效果与配置如下：

| 自然语言描述 | 对应概念 | PPTX 效果 / 配置映射 |
| --- | --- | --- |
| **弹入 / 弹出 (Pop in)** | 带有少量过冲的放大进入 | `zoom`（结合起始 scale 0.95） |
| **滑入 / 飞入 (Slide in)** | 从屏幕下方或侧边平滑滑入 | `fly`（搭配短 duration） |
| **擦除 / 揭示 (Wipe / Reveal)** | 按方向逐渐展开内容 | `wipe`（适合图表 `chart` 与时间轴 `timeline`） |
| **渐现 (Fade in)** | 不透明度淡入 | `fade`（适合标题与文本） |
| **交错瀑布 (Stagger)** | 多个元素依次按微小延迟出现 | `trigger: "after-previous"` + `stagger: 0.2` |
| **同步并行 (In unison)** | 多个元素同时播放进入动画 | `trigger: "with-previous"` |
| **点击控制 (Presenter pacing)** | 演讲者按一次点击出现一组 | `trigger: "on-click"` |

## 五、麦肯锡级高密度视觉排版手艺标准 (McKinsey High-Density Craft Standards)

### 1. 【关键词 + 短句】标签化卡片结构 (Tag-Lead Framing)
在多列、卡片或网格排版中，严禁整段漫长文字的无差别填充。正文列表与卡片项必须采用“标签 + 短句”强排版结构：
- **格式**：`【粗体关键词/标签】+ 简洁结果句/说明`
- **示例**：
  - ❌ *通过全面重构核心下单流程，大幅减少了用户点击层级，最终交付周期缩短了 30%*
  - ✅ **【流程优化】** 交付周期缩短 30%
- **效果**：使卡片具有清晰的扫读锚点，在视觉上形成明确的文字层级。

### 2. 数据图表极简去噪与直接标注 (Direct Data Labeling & De-noising)
专业的咨询级数据图表必须遵循以下去噪与标注铁律：
- **去尽杂音**：删去 Excel/SVG 默认的厚边框、渐变背景、冗余图例与高对比度网格线（网格线若保留必须使用极淡虚线 `stroke="#1E293B" stroke-dasharray="2 2"`）。
- **直接数值标注 (Direct Labeling)**：条形图/柱状图必须将数值直接标注在柱体上方或内部；折线图直接在关键节点旁边标注数据，避免读者在图表与图例之间反复穿梭。
- **强调色聚焦 (Color as Insight)**：整张图表仅对需要突出对比的核心数据维使用 Accent 强调色，其余对比项统一使用中性灰/暗蓝。

### 3. 数据来源与截至日期规范区 (Footer Data Source Reservation)
每一个高密度数据页、图表页或 KPI 卡片页，底部必须硬性保留 12px 低对比度数据源注释区：
- **格式**：`数据来源：[机构/系统/报告名称] (截至 [YYYY QX / YYYY-MM])`
- **示例**：`数据来源：麦肯锡 2026 亚太数字转型报告 (截至 2026 Q2)`
